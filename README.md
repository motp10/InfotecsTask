# Infotexs logger

Проект содержит консольные приложения для записи логов в файл, отправки логов по TCP и отображения статистики принятых сообщений.

## Сборка

Требования: CMake 3.16+, компилятор с поддержкой C++17 и POSIX-сокеты.

```bash
cmake -S . -B build
cmake --build build --parallel
```

После сборки в папке `build` находятся:

- `file_logger` — запись сообщений в файл;
- `socket_logger` — отправка сообщений на TCP-сервер;
- `statistic_app` — приём сообщений и вывод статистики;
- `libfileLogger.a` — статическая библиотека файлового логгера;
- `libfileLogger.so` — динамическая библиотека файлового логгера.

## Запуск файлового логгера

```bash
./build/file_logger --file application.log --level low
```

Параметр `--level` задаёт минимальный уровень записываемых сообщений: `low`, `medium` или `high`.

После запуска приложение интерактивно запрашивает текст сообщения и его уровень
важности. Уровень можно указать как `low`, `medium` или `high`; пустая строка
использует уровень из параметра `--level`. Пустые сообщения и неизвестные уровни
не записываются. Сообщение записывается в файл только если его уровень не ниже
заданного в `--level`.

Например, при `--level medium` сообщения уровня `low` отфильтровываются, а
сообщения `medium` и `high` добавляются в файл. Для завершения программы
передайте конец ввода (`Ctrl+D` в Linux/macOS или `Ctrl+Z`, затем `Enter` в
Windows); очередь будет закрыта, а рабочий поток завершит запись уже принятых
сообщений.

## Запуск сетевого логгера и сервера статистики

Сначала в первом терминале запустите сервер:

```bash
./build/statistic_app -t 5 -n 10
```

Во втором терминале подключите сетевой логгер:

```bash
./build/socket_logger --host 127.0.0.1 --port 8080 --level low
```

Если сервер недоступен, `socket_logger` выведет сообщение об ошибке и завершится с кодом `1`.

## Тесты

Запуск всех unit-тестов:

```bash
ctest --test-dir build --output-on-failure
```

Или запуск тестового исполняемого файла напрямую:

```bash
./build/tests/unit/unit_tests
```

Для запуска отдельного теста через CTest:

```bash
ctest --test-dir build -R unit_message_parser --output-on-failure
```

## Архитектура проекта

Проект разделён на несколько независимых компонентов:

- **FileLogger** — записывает сообщения в файл и работает в отдельном рабочем потоке через потокобезопасную очередь сообщений.
- **SocketLogger** — устанавливает TCP-соединение с сервером и отправляет отформатированные сообщения.
- **StatisticApp** — принимает сообщения от `SocketLogger`, десериализует их и передаёт в `Statistics`.
- **Statistics** — хранит и рассчитывает статистику по принятым сообщениям.
- **StatisticPrinter** — отвечает только за вывод рассчитанной статистики в консоль.
- **MessageFormatter / MessageDeserializer** — отвечают соответственно за сериализацию и десериализацию сообщений.
- **ArgumentParser** — разбирает аргументы командной строки каждого приложения.
- **Common library** — содержит общие компоненты, используемые несколькими частями проекта, например уровни важности и работу со временем.

Взаимодействие сетевого логгера и приложения статистики происходит по TCP:

`SocketLogger → TCP → Server → MessageDeserializer → Statistics → StatisticPrinter`

Файловый логгер использует другую схему:

`MessageParser → MessageQueue → FileLogger`
